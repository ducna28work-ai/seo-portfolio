# SEO Content Audit

A practical project demonstrating a structured approach to auditing multiple website URLs, identifying content issues, prioritizing improvements, and documenting SEO recommendations.

## Purpose

An SEO content audit helps identify content that may be:

- Outdated
- Thin or incomplete
- Misaligned with search intent
- Overlapping with other pages
- Missing important on-page elements
- Difficult to navigate or understand
- Underperforming relative to its intended purpose

This project demonstrates how an SEO audit can be organized into a repeatable workflow rather than relying on isolated page-by-page observations.

## Audit Workflow

**URL Collection → Page Review → Search Intent Analysis → Content Evaluation → On-Page Review → Internal Linking Review → Issue Classification → Prioritization → Recommendations → QA**

## Audit Scope

The audit can review the following areas:

### 1. Search Intent

Determine whether the page matches the expected intent behind its target query.

Typical intent categories include:

- Informational
- Commercial investigation
- Transactional
- Navigational

### 2. Content Quality

Review whether the content is:

- Relevant
- Useful
- Sufficiently comprehensive
- Clearly structured
- Up to date
- Appropriate for the intended audience

### 3. Content Structure

Review:

- Title
- Headings
- Introduction
- Section organization
- Content hierarchy
- FAQ or supporting sections where appropriate

### 4. On-Page SEO

Review key elements such as:

- Title tag
- Meta description
- H1
- Heading structure
- Primary topic coverage
- Internal links
- Image usage and alternative text where relevant

### 5. Internal Linking

Review whether the page:

- Links to relevant supporting content
- Receives links from related pages
- Uses descriptive anchor text
- Fits logically within the site's content architecture

### 6. Content Overlap

Identify potential overlap between pages targeting similar topics or search intent.

Potential outcomes include:

- Keep separate
- Differentiate intent
- Consolidate
- Redirect
- Reposition the target keyword

## Audit Record

Each audited URL can be documented using:

| Field | Description |
|---|---|
| URL | Audited page |
| Page Type | Product, service, category, article, or other page type |
| Primary Topic | Main topic covered by the page |
| Search Intent | Intended search intent |
| Content Status | Current content assessment |
| Main Issue | Most important identified issue |
| Issue Type | Classification of the issue |
| Priority | Recommended priority |
| Recommendation | Proposed action |
| QA Status | Final review status |

## Issue Classification

Issues can be classified into categories such as:

| Issue Type | Description |
|---|---|
| Intent Mismatch | Content does not sufficiently satisfy the intended search intent. |
| Thin Content | Page provides insufficient useful information for its purpose. |
| Outdated Content | Important information is no longer current. |
| Content Gap | Important subtopics or information are missing. |
| Structure Issue | Content hierarchy or organization needs improvement. |
| On-Page Issue | Important SEO elements require optimization. |
| Internal Linking | Relevant internal linking opportunities are missing or weak. |
| Content Overlap | Multiple pages address substantially similar topics or intent. |

## Prioritization

Issues can be prioritized based on:

- SEO impact
- User impact
- Business relevance
- Implementation effort

A practical prioritization approach is:

**High → Medium → Low**

### High Priority

Issues that may materially affect search intent alignment, important landing pages, content usability, or significant duplication/overlap.

### Medium Priority

Issues that can improve relevance, structure, internal linking, or content depth but are less urgent.

### Low Priority

Minor improvements that provide incremental value after higher-priority issues have been addressed.

## Recommendation Framework

Each recommendation should answer:

1. What is the problem?
2. Why does it matter?
3. What should be changed?
4. Which page element should be changed?
5. What should be reviewed after implementation?

The objective is to make recommendations actionable rather than simply identifying problems.

## Quality Assurance

Before finalizing an audit:

- Confirm the URL is correct.
- Confirm the page type.
- Confirm the intended search intent.
- Confirm each issue is supported by observable page evidence.
- Confirm recommendations address the identified issue.
- Confirm priorities are applied consistently.
- Check for potential content overlap.
- Review the final recommendations for clarity.

## Limitations

This project demonstrates an SEO content audit methodology.

It does not present confidential client data, private analytics, or proprietary SEO performance information.

Any future audit examples should use public, synthetic, or appropriately anonymized information.
